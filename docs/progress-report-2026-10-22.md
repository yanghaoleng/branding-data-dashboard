# 品牌自媒体传播数据看板阶段汇报

日期：2026-10-22（北京时间）。依据最初PRD、后续范围调整、当前源码和真实采集记录整理。

## 当前判断

**看板、后端存储及任务框架已部署，可进行阶段性功能预验收；完整、及时、稳定的真实作品数据采集尚未达成，不能视为V1.0整体验收通过。**

目前可以检查产品是否便于使用、统计规则是否正确、数据边界是否清楚；还不能用它回答品牌真实的完整总播放、总互动和跨平台贡献。

## 一、最初目标与当前达成情况

原目标是把抖音、小红书、视频号的多账号数据统一采集、汇总和可视化，降低逐个平台人工统计的成本，回答整体表现、平台贡献和重点账号/内容三个问题。后续明确优先自媒体，达人和媒体发稿暂缓；采集方向调整为主动读取公开账号，品牌后台权限不是这轮验证的前提。

| 目标 | 当前完成情况 | 尚未达成 / 验收边界 |
| --- | --- | --- |
| 多平台、多账号统一管理 | 已实现平台/账号配置、稳定身份、账号归属标记和独立任务 | 三平台真实数据源未全部接通；视频号未实测 |
| 整体、平台、账号、内容四层查看 | 已实现总览、平台与账号下钻、内容明细、排行、导出 | 完整真实作品集尚未形成，当前完整交互主要由明确标注的合成数据演示 |
| 按作品发布时间统计 | 已实现北京时间筛选、最新有效累计快照、平台+账号+内容身份去重 | 真实平台发布时间及分页完整性仍需逐项核实 |
| 及时、高效的爬虫 | 已实测匿名HTTP和浏览器渲染两条路线；取得三账号部分真实信息 | 未完成稳定作品ID、完整作品列表、播放/观看及互动明细；未证明每日有效同步 |
| 定量直观分析 | 已实现累计规模、发布日期分布、平台/账号比较、内容集中度、散点与议题分布 | 数据完整前不能给出完整品牌贡献、真实效果排行或效率结论 |
| 定性分析 | 已实现可解释的标题关键词归类及人工议题标注 | 未实现完整AI语义、情感、策略与因果分析；复杂AI策略不属于原PRD首期 |
| 数据质量与异常可见 | 缺失不填零、简写不伪装精确值、账号串数拒绝、失败保留有效快照、来源和时间可查 | 真实平台准确性、长期完整性和性能规模仍需验证 |
| 云端可访问和项目交接 | 已部署独立前端与API，具备访问保护、版本切换及升级前数据库备份 | 正式业务数据尚未接入；不能据此宣称全链路业务可用 |

## 二、真实爬虫验证结果

使用Node.js、Crawlee 3.18.2，比较CheerioCrawler直接读取网页和PlaywrightCrawler调用Chrome渲染网页。当前使用独立匿名会话，未使用品牌后台凭据；遇验证码停止该账号后续请求。

| 样本 | 已取得 | 当前限制 |
| --- | --- | --- |
| 抖音：叫叫阅读官方账号 | 身份、页面粉丝11.9万（简写）、账号累计获赞1,504,885、平台返回作品数521 | 普通HTTP未取得有效资料；浏览器作品列表服务异常，未取得作品级指标；521不是已采集作品数 |
| 小红书：叫叫阅读官方账号 | 两次HTTP均返回32条首屏笔记预览，含标题、部分点赞和待核验页面时间 | 作品ID全部为空，未完成详情和分页；不能正式去重入库 |
| 小红书：叫你摸会儿鱼 | 首次HTTP返回32条首屏预览 | 第二次HTTP跳转验证码页，已停止请求并保留前次有效快照；作品ID全部为空 |

两个小红书账号的4次HTTP请求中，3次返回预览、1次遇验证码。样本极少，且返回的是部分预览，不能据此宣称长期75%采集成功率。浏览器路线的两个小红书账号均跳转登录页。

现有结果为3个账号身份和64条观察记录，**满足正式作品入库条件的记录为0；3个账号均未通过完整作品及核心指标采集验收**。这表示采集未完整，并非真实播放或互动为0。正式数据库账号/作品/日志目前为空，公开快照独立展示。

尚未把所讨论的10个开源仓库逐一运行比较；本次实际运行的是同一框架下的两条采集路线。不能把选型研究当成性能或成功率验证。

## 三、开发过程与技术交付

1. 根据PRD明确自媒体优先，统一“发布时间筛选、最新累计快照、缺失不填零”的规则。
2. 完成React/Vite/Recharts看板，提供总览、内容分析、采集管理及明确标识的演示空间。
3. 完成Python/SQLite后端、导入校验、账号配置、管理员与采集器权限隔离、任务队列和租约协议。6/12/24小时配置是已实现的调度能力，实际平台同步仍依赖已适配且在线的采集器。
4. 部署独立站点路径与服务，保留版本回滚入口，并核验线上资源、API和访问保护。
5. 按指定账号执行公开采集PoC，解析并筛选真实样本，增加“公开采集实测”页面，明确暴露登录、缺失和验证码问题。
6. 检查源码及提交历史中的密钥风险，整理公开仓库、部署交接与本次阶段汇报。

原PRD要求先验证采集能力再锁定交付范围；实际当前先形成了可用的产品和存储框架，再完成上述公开PoC。采集验收仍是未完成项，界面上线不代表V1.0整体完成。

代码里保留了授权可见页/导入的通用框架，作为可选能力；它不代表当前必须通过品牌后台取数。公开采集验证脚本仍是PoC，并未接成全天候生产采集任务。

## 四、已经验证与尚未验证

- 15项JavaScript和18项Python测试通过，共33项，覆盖统计规则、缺失、身份隔离、幂等、任务状态和公开解析等。这不是平台采集成功率。
- 本地浏览器完成筛选联动、内容下钻、正式空间登录和公开实测页面检查。
- 线上HTML、JS、CSS、公开JSON与发布产物一致；健康接口正常；正式数据匿名访问被拒绝；管理员与采集器权限分离。2026-10-22再次检查服务和Nginx配置正常。
- 尚未完成普通账号登录后采集、三平台完整作品明细、真实数值逐项对照、连续多日同步，以及规模化的3秒查询性能验收。
- 移动端已写响应式样式，但没有实际手机截图验收；线上自动化浏览器曾超时，HTTP检查不能替代完整线上交互验收。

## 五、请先做一次阶段性预验收

请先打开看板，看看现有方向是否满足业务使用习惯，并反馈哪些方面需要加强：

1. **业务与页面：** 总览→平台→账号→内容的查看路径是否清楚，筛选、排行和导出是否够用，最需要补充哪些信息？演示数据仅用于体验功能。
2. **指标口径：** 是否认可按发布时间筛选、展示最新累计值；缺失、部分、过期与异常的提示是否清楚？
3. **分析能力：** 现有定量图表和人工/规则议题是否有用，下一步最希望回答哪些内容分析问题？
4. **真实采集：** 请重点检查实测页。哪些字段是上线必需，哪些缺失可以接受；确认首批账号、更新频率和优先打通的平台。
5. **优先级：** 请给出阻碍使用的问题和可后续增强的问题。本次预验收不代表完整真实采集已验收通过。

## 六、建议下一步

- P0：先选一个平台打通稳定作品ID、发布时间、原文链接、分页和可取得的明细指标；明确不能取得的播放/观看字段。
- P0：验证普通浏览账号登录后的公开可见数据，记录账号/会话失效和人工处理流程，不以品牌后台为必备条件。
- P0：建议以连续7天、每日至少一次有效同步、样本人工对照和失败恢复作为下一轮验收条件。此条件为下一步建议，尚未执行。
- P1：确认数据覆盖后，再加强跨账号比较、内容议题和复盘能力，避免用不完整数据生成完整业务结论。
- P1：补充视频号实测、实际手机操作及查询性能验证。
