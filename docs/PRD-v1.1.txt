# 品牌自媒体传播数据看板 PRD

**文档版本：** V1.1 修订版  
**产品阶段：** V1.0｜自媒体矩阵  
**文档状态：** 待研发评审  
**目标用户：** 品牌负责人、品牌传播团队、自媒体运营团队

---

## 一、项目背景与产品目标

### 1.1 项目背景

品牌目前通过三类主要触点开展传播：

- 自媒体矩阵
- 达人内容
- 公关媒体内容

第一阶段优先建设自媒体矩阵传播数据看板，覆盖抖音、小红书、微信视频号等平台，并支持同一平台下的多个账号。

当前主要问题：

1. **数据分散：** 不同平台、不同账号的数据需要分别查看。
2. **统计成本高：** 人工收集、汇总传播数据耗时。
3. **缺少整体视角：** 无法快速了解品牌自媒体矩阵整体的播放量与互动量。
4. **缺少横向比较：** 难以直观比较各平台、各账号的传播贡献。
5. **数据更新不连续：** 缺乏统一、稳定的数据更新机制。

### 1.2 产品目标

建立一个支持多平台、多账号数据采集和传播效果可视化的统一看板。

V1.0聚焦解决三个核心问题：

**① 品牌整体传播表现如何？**

通过总播放/观看量、总互动量，快速了解所选周期发布内容的传播规模。

**② 哪个平台贡献最大？**

展示抖音、小红书、视频号的播放/观看量与互动量及其贡献占比。

**③ 哪些账号和内容表现突出？**

通过账号对比和内容排行，识别主要传播贡献来源。

### 1.3 V1.0范围

**包含：**

- 多平台、多账号接入与数据同步
- 播放/观看量和互动量统一统计
- 按内容发布时间进行筛选
- 品牌整体、平台、账号、内容四个统计层级
- 核心指标可视化
- 数据更新状态与异常提示

**不包含：**

- 达人及公关媒体传播数据
- 品牌搜索、A3及销售转化分析
- 历史作品在当前周期产生的新增播放量分析
- 复杂的跨周期传播效果归因
- AI传播策略分析
- 复杂的内容质量评分
- 自动发布、评论、私信等操作

## 二、核心统计规则

### 2.1 唯一统计原则

**所有数据统一按照内容发布时间筛选。**

用户选择一个时间范围后，系统仅统计该范围内发布的内容，并展示这些内容截至最新有效采集时间的累计传播数据。

例如：

| 选择时间 | 统计内容 |
|---|---|
| 本周 | 本周新发布作品的累计数据 |
| 上周 | 上周发布作品的累计数据 |
| 本月 | 本月新发布作品的累计数据 |
| 上月 | 上月发布作品的累计数据 |
| 自定义 | 指定日期范围内发布作品的累计数据 |

假设：

- A作品于10月5日发布，累计播放10万。
- B作品于10月20日发布，累计播放5万。
- 用户选择10月19日至25日。

系统只纳入B作品，显示5万播放量。

A作品即便在10月19日至25日期间获得新增播放，也不纳入该周期统计。

### 2.2 数据持续更新规则

作品指标使用截至最新有效采集时间的累计数值。

因此，用户在不同日期查看同一发布周期，其累计播放量和互动量可能变化。

V1.0不设置历史统计值冻结机制。

数据采集从账号接入后开始持续记录；不要求批量追溯接入前的历史作品。对于尚未纳入采集范围的历史内容，应明确提示数据覆盖限制。

### 2.3 时间规则

时间筛选使用北京时间（UTC+8）。

- 本周：周一00:00至当前时间
- 本月：当月1日00:00至当前时间
- 上周、上月：对应完整自然周期
- 自定义：按用户选择的起止日期

页面展示：

- 内容发布时间范围
- 数据最近同步时间或同步状态

不得将内容发布时间与数据采集时间混为一谈。

### 2.4 总播放/观看量

**定义：**

所选发布时间范围内，所有符合条件作品的最新有效累计播放/观看次数之和。

计算：

`总播放/观看量 = Σ 符合条件作品的最新有效播放/观看次数`

各平台使用其创作者后台可获取的作品播放或观看指标。

规则：

- 曝光量不直接等同于播放/观看量。
- 同一作品重复采集不得重复计数。
- 缺失的观看指标不得当作0。
- 平台原始指标定义应予保留。
- 不同平台指标可能存在统计口径差异，跨平台汇总属于管理口径的合计。

无法获取观看指标的平台或作品，应标记数据缺失，不能通过估算填补。

### 2.5 总互动量

统一使用以下基础互动行为：

`总互动量 = 点赞量 + 评论量 + 收藏量 + 分享量`

规则：

1. 优先获取创作者后台原始指标。
2. 平台不提供的互动类型标记为“不适用”。
3. 应有但未采集成功的指标标记为“缺失”。
4. 可获得的互动数据仍可展示，但必须区分完整与部分数据。
5. 当参与比较的平台指标覆盖范围不一致时，不得将互动贡献占比解释为完整、同口径的品牌贡献。

V1.0不以互动率作为核心考核指标，暂不提供复杂的跨平台互动效率排名。

### 2.6 发布内容数

统计所选周期内发布的去重作品数量。

唯一内容标识：

`平台ID + 账号ID + 内容ID`

重复采集不能增加作品数量。

### 2.7 数据有效性

核心指标至少区分以下状态：

| 状态 | 含义 |
|---|---|
| 完整 | 应采集的作品及适用指标已成功获取 |
| 部分 | 部分作品或指标缺失，当前数值不是完整合计 |
| 异常 | 采集失败、登录失效或数据长时间未更新 |
| 暂无数据 | 已完成有效采集，但筛选范围没有符合条件的作品 |

数据不完整时仍可显示已采集数值，但必须标识为“部分数据”，不能作为完整品牌总量使用。

## 三、产品信息架构

V1.0采用**一个传播数据看板 + 一个数据采集管理页面**。

```text
品牌自媒体传播数据看板
│
├── 01 自媒体传播总览
│   ├── 全局筛选
│   ├── 核心传播指标
│   ├── 发布内容表现分布
│   ├── 分平台传播表现
│   ├── 分账号传播表现
│   └── TOP传播内容
│       └── 内容详情
│
└── 02 数据采集管理
    ├── 平台账号管理
    ├── 数据同步状态
    └── 异常处理
```

**设计原则：**

通过统一筛选与下钻完成不同层级分析，不为抖音、小红书和视频号分别开发独立看板。

点击平台或账号后，复用原看板结构，更新筛选范围。

## 四、页面01：自媒体传播总览

### 4.1 页面目标

让用户快速完成以下分析：

**整体传播规模 → 平台贡献 → 账号表现 → 重点内容**

桌面端优先设计。

### 4.2 模块一：全局筛选

| 筛选项 | 选项 |
|---|---|
| 发布时间 | 本周、上周、本月、上月、近7天、近30天、自定义 |
| 平台 | 全部、抖音、小红书、视频号 |
| 账号 | 全部或指定账号，支持多选 |
| 内容类型 | 全部、视频、图文（数据支持时） |

默认：

- 时间：近30天
- 平台：全部
- 账号：全部

交互要求：

- 所有模块共享筛选条件。
- 切换平台后，账号列表同步过滤。
- 支持重置筛选。
- 页面下钻及返回时保留筛选状态。
- 所有时间筛选均作用于内容发布时间。

### 4.3 模块二：核心KPI

首页显示四张指标卡。

**一级核心指标：**

1. 总播放/观看量
2. 总互动量

**二级辅助指标：**

3. 发布内容数
4. 有效统计账号数

每张核心指标卡至少显示：

- 指标名称
- 当前数值
- 数据完整性状态

页面统一提供数据更新时间信息。

有效统计账号数指当前筛选范围内成功完成有效同步的账号数量；没有发布新内容但同步成功的账号也可计入。

**V1.0不展示默认环比增长率。**

原因：不同发布周期的内容，获得累计传播的时间不同，直接比较累计量容易产生误导。

### 4.4 模块三：发布内容表现分布

用于查看所选时间范围内，不同发布日期作品的传播表现。

**图表：柱状图**

支持切换：

- 播放/观看量
- 互动量

统计逻辑：

按照作品发布日期分组，将同一日期发布的作品最新累计指标相加。

例如，10月20日发布3条内容，其累计播放量分别为1万、2万、3万，则10月20日对应柱形值为6万。

**注意：**

这不是10月20日实际产生的播放量，而是10月20日发布作品截至最新同步时间的累计表现。

V1.0不提供真实日新增传播趋势和复杂时间粒度切换。

### 4.5 模块四：分平台传播表现

**目标：** 直观比较各平台的传播规模与贡献。

展示两个维度：

- 各平台播放/观看量
- 各平台互动量

采用横向条形图，分别按数值排序。

同步提供明细表：

| 平台 | 发布内容数 | 播放/观看量 | 互动量 | 数据状态 |
|---|---:|---:|---:|---|
| 抖音 | — | — | — | — |
| 小红书 | — | — | — | — |
| 视频号 | — | — | — | — |
| 合计 | — | — | — | — |

在指标完整且具备可比条件时，展示平台贡献占比。

`平台播放贡献占比 = 平台播放量 ÷ 各平台播放量合计`

互动贡献占比同理，但必须注意互动字段覆盖范围。

若某平台数据缺失或统计不完整：

- 保留已采集数据及状态标识。
- 不将部分数据冒充完整贡献。
- 不显示缺乏可靠依据的完整贡献百分比。

点击平台，可将该平台设为当前筛选条件，进一步查看账号与内容表现。

### 4.6 模块五：分账号传播表现

**目标：** 识别品牌矩阵内不同账号的传播贡献。

展示表格：

| 字段 | 说明 |
|---|---|
| 平台 | 所属平台 |
| 账号名称 | 当前显示名称 |
| 发布内容数 | 所选周期发布作品数量 |
| 播放/观看量 | 所选作品累计指标 |
| 互动量 | 所选作品累计指标 |
| 平台内播放贡献 | 数据完整时计算 |
| 数据状态 | 正常、部分、异常 |
| 最近同步时间 | 最近成功采集时间 |

交互：

- 按播放/观看量、互动量排序。
- 支持账号名称搜索。
- 支持平台分组。
- 点击账号后筛选其内容及传播数据。

账号必须使用稳定的平台账号ID识别，不能以昵称作为唯一标识。

### 4.7 模块六：TOP传播内容

**目标：** 快速识别所选周期中最有传播表现的作品。

默认展示TOP10。

字段：

- 作品封面
- 作品标题
- 所属平台
- 所属账号
- 发布时间
- 播放/观看量
- 互动量

排序：

- 默认按播放/观看量降序
- 支持切换互动量降序

支持查看更多作品。

点击作品进入简化内容详情，展示：

- 作品基本信息
- 原始作品链接
- 累计播放/观看量
- 点赞、评论、收藏、分享
- 最新数据采集时间

V1.0不开发独立的内容历史分析页面。

## 五、页面02：数据采集管理

### 5.1 页面目标

支持管理员管理平台账号，检查数据同步情况，并处理必要异常。

不建设复杂的数据采集运维系统。

### 5.2 平台账号管理

支持：

- 新增授权账号
- 查看已接入账号
- 检查授权状态
- 重新授权
- 暂停、恢复采集
- 移除账号

账号列表展示：

| 字段 | 说明 |
|---|---|
| 平台 | 抖音、小红书、视频号 |
| 账号名称 | 平台当前昵称 |
| 账号ID | 稳定身份标识 |
| 授权状态 | 正常、失效、异常 |
| 采集状态 | 正常、采集中、失败、暂停 |
| 最近成功同步时间 | 最近有效同步时间 |

### 5.3 数据采集任务

V1.0目标：

**每个正常接入且具备可用采集能力的账号，每天完成至少一次有效数据同步。**

采集范围：

1. 账号基本信息
2. 账号作品列表
3. 作品ID及发布时间
4. 作品类型和原始链接
5. 播放/观看量
6. 点赞、评论、收藏、分享
7. 实际采集时间

对于已纳入系统的作品，持续更新其可获取的累计指标。

**V1.0不要求批量补采账号接入前的历史作品。**

支持：

- 每日定时采集
- 手动触发同步
- 查看任务状态
- 查看失败原因
- 重新授权与重试

### 5.4 异常处理

| 异常 | 处理 |
|---|---|
| 登录授权失效 | 提示重新授权 |
| 网络或任务失败 | 记录异常，允许有限次数重试 |
| 作品列表读取不完整 | 标记本次采集不完整 |
| 播放或互动字段缺失 | 标记部分数据 |
| 平台访问受限 | 暂停对应任务，等待处理 |
| 长时间未同步 | 显示数据过期提示 |

某一平台或账号采集失败，不得影响其他账号正常同步。

允许使用最近一次有效数据进行展示，但必须明确其数据状态及更新时间。

不得通过绕过验证码、访问控制等方式保证采集成功。

## 六、数据结构与计算要求

### 6.1 最小数据结构

V1.0建议保留四类核心数据表。

| 数据表 | 主要作用 |
|---|---|
| `accounts` | 平台及账号信息、授权和同步状态 |
| `contents` | 内容ID、所属账号、发布时间、类型及链接 |
| `content_metrics_daily` | 每日作品累计指标快照 |
| `collection_logs` | 采集任务状态、时间及错误摘要 |

作品指标快照保存：

- 平台ID
- 账号ID
- 内容ID
- 快照日期
- 播放/观看量
- 点赞量
- 评论量
- 收藏量
- 分享量
- 采集时间
- 有效性状态

唯一键：

`平台ID + 账号ID + 内容ID + 快照日期`

同一天重复采集时，以最新成功且通过校验的有效快照作为当天结果。

快照用于数据留存、核验与异常排查。

**V1.0不基于快照开发真实日增量分析、历史版本回放或复杂周期对比。**

### 6.2 数据查询逻辑

统一执行：

`发布时间筛选 → 平台/账号筛选 → 获取每条作品最新有效指标 → 按层级汇总`

品牌整体、平台、账号及内容的指标必须使用同一套计算规则。

### 6.3 数据质量要求

重点保证：

1. 同一内容不会重复计数。
2. 同一账号的数据不会混入其他账号。
3. 发布日期准确。
4. 作品列表采集范围可核验。
5. 缺失值不自动填0。
6. 不同平台的原始指标口径可追踪。
7. 不完整数据不能被解释为完整品牌总量。

对于列表采集，应区分“采集器正常完成读取”和“已确认平台作品完整覆盖”，不能仅因已发现作品的指标全部读取成功，就认定账号数据完整。

## 七、技术方案与可行性验证

### 7.1 技术方向

采用多平台采集适配器，统一输出作品与指标数据。

现有GitHub技术候选：

**CreatorHub**  
https://github.com/3441293738/creatorhub

**creator-platform-data**  
https://github.com/orangexie05/creator-platform-data

以上项目仅作为技术验证候选，不代表已确认具备全部采集能力或代码商用授权。

技术选型应优先考虑：

- 实际作品指标获取能力
- 多账号支持
- 采集稳定性
- 数据准确性
- 软件许可及平台规则合规性

### 7.2 PoC验证范围

正式开发看板之前，先验证三类平台的数据采集能力。

每个平台至少使用一个有权管理的测试账号。

重点验证：

| 验证项 | 验证目标 |
|---|---|
| 账号登录 | 能够合法接入授权账号 |
| 作品列表 | 能获取指定范围作品及发布时间 |
| 播放/观看量 | 能获取后台真实可核验指标 |
| 互动数据 | 能获取哪些字段，哪些无法获取 |
| 数据准确性 | 采集数值与平台后台核验一致 |
| 多账号隔离 | 不同账号数据不会混淆 |
| 连续采集 | 多日重复同步能够保持稳定 |

对作品列表，应检查分页完整性，并抽样与平台后台作品清单核对。

### 7.3 实施原则

**通过验证的平台与字段才能进入正式交付范围。**

如果某个平台无法稳定获取核心数据，应标记为暂不支持或部分支持，而不是采用不可靠数据补齐。

不得因为一个平台的采集问题阻塞其他已经验证通过的平台上线。

## 八、开发优先级

### 8.1 P0｜V1.0必须实现

## 九、非功能要求

### 9.1 数据安全

- 仅接入有权管理的品牌账号。
- 优先使用平台官方允许的数据接口或导出机制。
- 非官方采集方式须进行规则及合规审查。
- 登录凭据与会话信息安全保存。
- 不在普通日志中存储原始Cookie、密码等敏感数据。
- 数据采集权限以必要读取权限为限。

### 9.2 稳定性

- 账号采集任务相互隔离。
- 采集失败不影响已有数据查询。
- 页面明确展示数据过期或缺失状态。
- 系统支持必要的人工重试。

### 9.3 性能

首期建议：

- 常规筛选下，首页核心统计数据3秒内返回。
- 作品列表支持分页。
- 看板查询和采集任务分离。
- 按首批账号及作品规模选择适当的数据存储方案。

## 十、V1.0验收标准

### 10.1 数据采集验收

1. 可以接入已通过技术验证的平台及授权账号。
2. 可以读取约定范围内的作品列表。
3. 可以获取已确认支持的播放与互动字段。
4. 多次同步同一作品不会产生重复记录。
5. 作品发布时间及内容归属正确。
6. 能够完成定期数据更新。
7. 采集异常有明确状态和原因。
8. 不完整或不可用的数据不会被当作完整数值。

### 10.2 看板功能验收

**测试一：时间筛选**

选择“本周”后，只统计本周新发布的内容。此前发布的作品不得计入。

**测试二：核心指标**

总播放/观看量、总互动量与符合条件的作品明细汇总一致。

**测试三：平台筛选**

选择某个平台后，所有模块只展示该平台符合条件的内容及数据。

**测试四：账号筛选**

选择指定账号后，核心KPI、分布图及内容排行同步更新。

**测试五：层级汇总**

在完整且一致的数据范围内：

- 品牌整体 = 各平台合计
- 平台合计 = 平台下各账号合计
- 账号合计 = 账号下符合条件的作品合计

**测试六：异常状态**

当某账号采集失败或字段缺失时：

- 不显示虚假的0值。
- 不将部分数据标记为完整。
- 其他账号继续正常展示。

### 10.3 产品完成定义

V1.0交付完成后，品牌负责人无需逐个平台、逐个账号人工汇总，就能够：

**① 选择某个发布时间范围，查看该期间发布内容的总播放/观看量和总互动量。**

**② 直观比较不同平台、不同账号的传播表现。**

**③ 找到贡献突出的内容，并查看原始作品。**

**④ 判断当前统计数据是否完整、是否及时更新。**

## 十二、产品总结

品牌自媒体传播数据看板V1.0聚焦一个明确目标：

**把分散在不同平台、不同账号中的新发布内容传播数据，统一采集、汇总和可视化。**

第一阶段以总播放/观看量和总互动量为核心，支持时间、平台、账号三个主要筛选维度，以及内容排行和必要的数据下钻。

在数据层面，统一以内容发布时间作为统计依据，展示所选作品截至最新有效采集时间的累计传播表现，不增加不必要的历史增量分析。

在技术层面，优先验证核心数据能否稳定、准确获取，再进行看板开发。

**V1.0核心原则：统计口径清晰、数据真实可信、页面简单直观、开发范围可控。**
